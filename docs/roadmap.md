## 2. 良いところ

- **コンセプトがぶれていない**：「また聴きたい回だけを残す」に絞り、全機能がそこにつながっている。全放送を記録する負担がない。
- **無料・サーバーなし・プライバシー重視**：データは各自の端末の IndexedDB のみ。ログイン・解析なし。外部に出るのは検索語だけ。リンクを人に送っても、互いのデータは見えない。
- **記録の手間が少ない**：回の追加で番組を「登録済みから選ぶ／打って候補から選ぶ／そのまま手入力」でき、先に番組登録しなくてよい（v1.3.0）。番組名の自動候補（Apple Podcasts）、放送局・配信元チップ、いつもの出演者の自動セット、前回と同じ出演者、よく出る人、打っただけで保存、YouTube の題名・チャンネル名の取得。
- **聴き返すまで1タップ**：回ごとに radiko・Spotify・Apple Podcasts・YouTube などのリンクを残せる。日付が分からない回も「日付なし」で残せる。
- **ラジオ以外にも使える**：Podcast・YouTube・配信のアーカイブも同じ仕組みで記録できる（アプリ名は Radio Log のまま）。
- **見返す楽しさ**：並び替え（番組ごと等）、出演者の AND 絞り込み、🎲 おまかせ1本、シェア画像（1回・上位5件）。
- **おすすめを交換できる**：10件まで選んでリンクで送れる。受け取った人は別枠で見て、気に入った回だけ取り込める。サーバーなしで、中身は GitHub にも渡らない。
- **データを守る仕組み**：共有シートでのバックアップ、14日リマインド、置き換え復元（失敗時は元データを保持）、整合性ルール（1トランザクション、参照中の削除ブロック）。
- **スマホで完結**：PWA（ホーム画面に追加・オフライン）、片手操作の下部ナビ、レトロラジオ調のデザイン。
- **続けやすい土台**：設計ドキュメント、CLAUDE.md、E2E テスト 36 件がデプロイ前に自動実行（ブランチでも実行できる）。
- **データの形を変えても安全**：スキーマ v1 → v2 の自動移行と、v1/v2 両方のバックアップ取り込みをテストで確認している。

## 3. 改善できるところ（優先度順の目安）

> **方針（2026-11-26 決定）**：★1（リンク・日時を任意に）、★2（ラジオ以外への拡張）、★3（リスト共有）の3つ。3〜8 は保留（使ってみて必要になったら検討）。
> **進み具合**：★1＋★2 は **完了**（v1.1.0、スキーマ v2）、★3 も **完了**（v1.2.0、スキーマ変更なし）。いずれも 2026-11-26。次にやることは未定（3〜8 から、使ってみて必要になったものを選ぶ）。

### ★1 リンクを貼れるようにし、放送日とリンクは任意にする 【完了：v1.1.0】
- **実装したこと**：回の追加にリンク欄（最大5件・http/https のみ・サービス名の自動判定・表示名・radiko の期限注意）、詳細画面のリンクボタン、一覧カードのサービス名表示。放送・配信日は任意（「日付なし」ボタン）。日付なしは日付順の最後に「日付なし」でまとめ（追加した順）、重複確認なし、シェア画像は「日付なし」（ファイル名 `radio-log-nodate.png`）。`DB_VERSION` 2、v1 → v2 移行、バックアップ v1/v2 両対応。詳細は要求仕様 FR-5-8・FR-6-1・DR-7・DR-8。
- 以下は計画時のメモ（記録として残す）。
- **ねらい**：「どの回を聴きたいか」から「実際に聴く・見る」まで1タップでつなぐ。放送日が分からない回（YouTube の動画など）も残せるようにする。
- **案**：
  - 回の追加画面に「リンク」欄（radiko タイムフリー／Spotify／Apple Podcasts／YouTube など）。詳細画面にリンクボタン、一覧にアイコン。
  - **放送日・リンクはどちらも任意**（番組だけ必須）。放送日の初期値は今まで通り「今日」で、「日付なし」にもできる。
  - 日付なしの回：日付順の一覧では「日付なし」として最後にまとめる（追加した順で並べる）。重複確認（同じ番組・同じ放送日）は日付があるときだけ。シェア画像では「日付なし」と表示。
- **データ（スキーマ v2）**：`episodeLogs.links: { url, label? }[]` を追加、`broadcastDate` は空文字（日付なし）も許可。`DB_VERSION` を 2 にし、v1 → v2 の移行（既存データは `links: []`）、バックアップの検証を v1/v2 両対応にする（既存の JSON を壊さない）。インデックス `by_program_date` は空文字でも動作する。
- **注意点**：
  - URL は `http:` / `https:` のみ受け付ける（`javascript:` 等を弾く）。外部リンクは `rel="noopener noreferrer"`。
  - radiko のタイムフリーは期限（概ね1週間）がある旨を表示するとよい。
  - リンクを開くまで外部通信は発生しない（プライバシー方針は維持）。

### ★2 ラジオ以外（YouTube・Podcast・配信など）にも広げる 【完了：v1.1.0】
- **実装したこと**：文言を「番組・チャンネル名」「放送局・配信元」「放送・配信日」に。配信元チップ（YouTube・Podcast・Spotify・Voicy・stand.fm・ニコニコ・Twitch）を常に表示。ホームとガイドにラジオ以外も使える旨を追加。
- **YouTube の自動入力（調査結果）**：YouTube Data API はキーが必要なので不採用。キー不要の **oEmbed**（`https://www.youtube.com/oembed`）は GitHub Pages のオリジンからの CORS を許可していることを Actions 上で確認したため採用。**ボタンを押した時だけ**、貼った URL だけを送り、題名とチャンネル名だけを使う（埋め込み・サムネイルは使わない）。番組登録では動画 URL からチャンネル名＋配信元「YouTube」、回の追加では題名をリンクの表示名にし、同じ名前の番組を自動で選ぶ。
- 以下は計画時のメモ（記録として残す）。
- **ねらい**：今の仕組みはそのまま YouTube の動画やライブ配信のアーカイブにも使える。
- **案**：
  - 文言を「番組／放送局／放送日」から、必要に応じて「番組・チャンネル／配信元／放送・配信日」へ。放送局チップに「YouTube」「Podcast」などを追加。
  - ★1 のリンク欄に YouTube の URL を貼れるようにする。
  - YouTube URL からタイトルやチャンネル名を自動入力する案は **要調査**。YouTube Data API は API キーが必要なので不可（公開リポジトリに鍵を置けない）。キー不要の oEmbed がブラウザから直接呼べるか（CORS）、規約上問題ないかを確認してから判断する。
- **注意点**：アプリ名（Radio Log）は変えない方針。ホームのキャッチコピーと使い方ガイドの説明を広げる程度にする。

### ★3 リスト共有（10個までまとめて他の人に送る） 【完了：v1.2.0】
- **実装したこと**：リピート帳「📨 選んでシェア」→ 最大10件を選ぶ → メモを含めるか（既定は含めない・各200文字）→ 相手に見える内容のプレビュー → 共有シート／リンクをコピー／ファイルで送る。リンクは `#/shared/<形式バージョン＋圧縮＋base64url>`。受け取りは「シェアされたリスト」画面（S9）で、開いただけでは保存しない。1件ずつ・まとめて取り込み（1トランザクション、名前・別名で照合、重複は確認、既存の番組・出演者は変更しない）。受け取ったデータは厳しく検証し、1か所でも不正なら全体を読み込まない。詳細は要求仕様 FR-1-7・FR-1-8・S9（FR-9-1〜9-6）・DR-9・NFR-13。
- **分かったこと**：メモ付きで10件だとリンクが数千文字になる。LINE などはメッセージの文字数に上限があり長いリンクは送れないことがあるので、4000文字超で注意を出し、「ファイルで送る」を用意した。
- 以下は計画時のメモ（記録として残す）。
- **ねらい**：おすすめの回を友人に渡し、相手が気に入ったものだけ自分のリピート帳に取り込める。
- **流れ**：
  1. **送る側**：リピート帳で「選んでシェア」→ 最大 **10 件** をチェック → 「メモも含める／含めない」を選ぶ → 相手に見える内容をプレビュー → 共有シート（LINE・X など）でリンクを送る。
  2. **受け取る側**：リンクを開くと **「シェアされたリスト」という別の画面** で表示される。この時点では自分のリピート帳には何も入らない。
  3. 気に入った回だけ **「＋ 自分のリピート帳に入れる」**（または「まとめて入れる」）。
- **仕組み（サーバー不要）**：選んだ回の内容（番組名・放送局・放送日〈日付なしも可〉・出演者と役割・リンク・メモ）を圧縮してリンクの `#` 以降に入れる（例：`…/radio-log/#/shared/xxxx`）。`#` 以降はサーバーに送られないので、GitHub にも中身は渡らない。
- **取り込みのルール**：番組・出演者は名前（別名・表記ゆれ込み）で照合し、あればそれを使い、なければ新しく作る。同じ番組・同じ放送日が既にあれば確認する。取り込んだ回は普通の回として扱う（スキーマ変更なし）。
- **注意点**：
  - リンクの長さ：メモは 1 件あたり 200 文字程度で切る等の上限を設ける。長すぎる場合はファイル（JSON）で送る方法にフォールバック。
  - 受け取ったデータは他人が作ったものとして厳しく検証する（形式・件数・文字数・URL は http/https のみ）。表示はテキストとして扱う。
  - リンクを知っている人は誰でも中身を見られる。送る前のプレビューで、メモに個人的なことが書かれていないか確認できるようにする。
  - 形式にバージョン番号を付け、将来の変更でも古いリンクを開けるようにする。

### 運用・技術の宿題
- **実機確認**：iPhone / Android で、共有ボタン（シェア画像・バックアップ）、ホーム画面に追加したときの動作、オフライン起動、データの残り方を確認する。
- **GitHub Actions**：E2E は緑で運用中。一度、並び替えテストがクリック直後の読み取りで不安定に落ちたため `expect.poll` で待つ形に直した（2026-11-26）。今後も「クリック直後に一度だけ読む」書き方は避ける。失敗したら Artifacts の「playwright-report」を見て修正。
- **YouTube oEmbed の継続確認**：YouTube 側の仕様変更で CORS や応答が変わる可能性がある。取得できなくなっても手入力で記録は続けられる（エラーは画面に出る）。
- **実機確認（v1.1.0）**：既存データのある端末で更新し、回が残っていること・リンクの追加と「YouTube から題名を取得」が動くことを確認する。
- **実機確認（v1.2.0）**：iPhone / Android で「選んでシェア」→ LINE で自分や家族に送り、受け取ったリンクを開いて（LINE 内のブラウザ・Safari・Chrome）「シェアされたリスト」が出ること、取り込めることを確認する。LINE 内ブラウザとふだんのブラウザではデータが別になる点も確かめる。
- **リスト共有の形式を変えるとき**：`SHARE_FORMAT_VERSION` を上げ、古い形式（1）も読めるようにする（すでに送られたリンクが開けなくならないように）。
- **package-lock.json をコミット**：依存のバージョンを固定し、ビルドを再現可能にする（一度 `npm install` した環境で生成）。
- **Actions のバージョン更新**：`actions/checkout@v4` 等が Node 20 の非推奨警告を出している。新しいメジャー版が出たら更新する。
- **旧ユーザー名が過去の変更履歴に残っている**：現在のファイルには無い。完全に消すには履歴の書き換え（force push）が必要で元に戻せないため、必要になったら判断する。
- **ドキュメントの更新**：機能を変えたら USM・要求仕様・このファイルを更新する（CLAUDE.md のルール）。

## 5. 既知の制約

- 番組名の候補は Apple Podcasts にある番組のみ（radiko のみ・Spotify 独占は手入力）。YouTube はチャンネル名を動画 URL から取得できる（非公開・埋め込み不可の動画は取得できない）。
- radiko のタイムフリーのリンクは放送後おおむね1週間で聴けなくなる（記録は残る）。
- データは端末ごと。URL（オリジン）が変わると別アプリ扱いで、移行はバックアップ → 復元。
- iPhone ではホーム画面に追加したアプリと Safari でデータが別々になることがある。シェアされたリンクを LINE 内のブラウザで開いて取り込むと、ふだんのアプリとは別の場所に入ることがある（ふだん使うブラウザで開き直す）。
- シェアのリンクは、知っている人なら誰でも中身を見られる（暗号化していない）。送る前のプレビューで確認する。
