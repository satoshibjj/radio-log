## 2. 良いところ

- **コンセプトがぶれていない**：「また聴きたい回だけを残す」に絞り、全機能がそこにつながっている。全放送を記録する負担がない。
- **無料・サーバーなし・プライバシー重視**：データは各自の端末の IndexedDB のみ。ログイン・解析なし。外部に出るのは検索語だけ。リンクを人に送っても、互いのデータは見えない。
- **記録の手間が少ない**：番組名の自動候補（Apple Podcasts）、放送局チップ、いつもの出演者の自動セット、前回と同じ出演者、よく出る人、打っただけで保存。
- **見返す楽しさ**：並び替え（番組ごと等）、出演者の AND 絞り込み、🎲 おまかせ1本、シェア画像（1回・上位5件）。
- **データを守る仕組み**：共有シートでのバックアップ、14日リマインド、置き換え復元（失敗時は元データを保持）、整合性ルール（1トランザクション、参照中の削除ブロック）。
- **スマホで完結**：PWA（ホーム画面に追加・オフライン）、片手操作の下部ナビ、レトロラジオ調のデザイン。
- **続けやすい土台**：設計ドキュメント、CLAUDE.md、E2E テスト 19 件がデプロイ前に自動実行。

## 3. 改善できるところ（優先度順の目安）

> **方針（2026-11-26 決定）**：次にやるのは **★1（リンク記録）と ★2（ラジオ以外への拡張）だけ**。3〜8 は保留（使ってみて必要になったら検討）。
> ★1 はスキーマ変更（v2）を伴う。★2 の文言・チップ拡張と同じタイミングで進めるとよい。

### ★1 聴ける場所・見られる場所のリンクを記録する 【次にやる】
- **ねらい**：「どの回を聴きたいか」から「実際に聴く」まで1タップでつなぐ。アプリの目的に最も効く。
- **案**：回ごとに URL を1つ以上保存（radiko タイムフリー／Spotify／Apple Podcasts／YouTube など）。詳細画面にリンクボタン、一覧にアイコン。
- **注意点**：
  - スキーマ v2（例：`episodeLogs.links: { url, label }[]`）。`DB_VERSION` を上げ、移行処理とバックアップ検証を更新する（既存データ・既存 JSON は壊さない）。
  - URL は `http:` / `https:` のみ受け付ける（`javascript:` 等を弾く）。外部リンクは `rel="noopener noreferrer"`。
  - radiko のタイムフリーは期限（概ね1週間）がある旨を表示するとよい。
  - リンクを開くまで外部通信は発生しない（プライバシー方針は維持）。

### ★2 ラジオ以外（YouTube・Podcast・配信など）にも広げる 【次にやる】
- **ねらい**：今の仕組みはそのまま YouTube の動画やライブ配信のアーカイブにも使える。
- **案**：
  - 文言を「番組／放送局／放送日」から、必要に応じて「番組・チャンネル／配信元／放送・配信日」へ。放送局チップに「YouTube」「Podcast」などを追加。
  - ★1 のリンク欄に YouTube の URL を貼れるようにする。
  - YouTube URL からタイトルやチャンネル名を自動入力する案は **要調査**。YouTube Data API は API キーが必要なので不可（公開リポジトリに鍵を置けない）。キー不要の oEmbed がブラウザから直接呼べるか（CORS）、規約上問題ないかを確認してから判断する。
- **注意点**：アプリ名（Radio Log）は変えない方針。ホームのキャッチコピーと使い方ガイドの説明を広げる程度にする。

### 3 メモの全文検索 【保留】
- リピート帳でメモ・番組名・出演者をまとめて検索。データは端末内なので追加の通信はない。

### 4 タグ（神回・企画回・ゲスト回 など） 【保留】
- 回に複数タグを付け、絞り込み・並び替えに使う。スキーマ変更が必要（やる場合は v3 以降。★1 の v2 と同時にやるかはその時に判断）。

### 5 番組の別名（略称） 【保留】
- `programs.aliases` を追加し、番組検索で略称でもヒットさせる。スキーマ変更が必要。

### 6 「聴き返した」記録 【保留】
- 聴き返した日・回数を残し、「まだ聴き返していない回」から おまかせ1本 を選べるようにする。

### 7 統計 【保留】
- よく出る出演者ランキング、月別の件数、番組別の割合など。

### 8 無料のクラウド同期（要調査） 【保留】
- 鍵を公開せずに使える方法に限る（例：利用者自身の Google ドライブを OAuth で使う等）。設定の手間・規約・審査を調べてから判断。

### 運用・技術の宿題
- **実機確認**：iPhone / Android で、共有ボタン（シェア画像・バックアップ）、ホーム画面に追加したときの動作、オフライン起動、データの残り方を確認する。
- **GitHub Actions**：初回の E2E 実行が緑になるかを確認する。失敗したら Artifacts の「playwright-report」を見て修正。
- **package-lock.json をコミット**：依存のバージョンを固定し、ビルドを再現可能にする（一度 `npm install` した環境で生成）。
- **Actions のバージョン更新**：`actions/checkout@v4` 等が Node 20 の非推奨警告を出している。新しいメジャー版が出たら更新する。
- **旧ユーザー名が過去の変更履歴に残っている**：現在のファイルには無い。完全に消すには履歴の書き換え（force push）が必要で元に戻せないため、必要になったら判断する。
- **ドキュメントの更新**：機能を変えたら USM・要求仕様・このファイルを更新する（CLAUDE.md のルール）。

## 4. やらないと決めたこと（再掲）

詳細は [USM の「やらないと決めたこと」](user-story-map.md#7-やらないと決めたこと)。

- 有名番組の初期データ同梱（すぐ古くなる）

- 指定メールアドレスへの自動送信（送信サーバーや鍵が必要、データが第三者を経由）
- 下部ナビの6枠化（スマホで押しにくい）
- 有料サービス・独自ドメイン

## 5. 既知の制約

- 番組名の候補は Apple Podcasts にある番組のみ（radiko のみ・Spotify 独占は手入力）。
- データは端末ごと。URL（オリジン）が変わると別アプリ扱いで、移行はバックアップ → 復元。
- iPhone ではホーム画面に追加したアプリと Safari でデータが別々になることがある。
